Shell injection part 2

Now that we know how our input changes the command that is executed, we can do more fun stuff.

On the previous page, I added some protections to make it so that you cannot do any kind of shell or code injection. Here is what that code looked like: 

    
    from subprocess import run
    from shlex import quote

    def call_date_safe(formatting: str = None):
        args = ["date"]

        if formatting:
            if not formatting.startswith("+"):
                formatting = "+" + formatting
            args.append(quote(formatting))

        out = run(args, capture_output=True)

Here I am calling the date command by passing in an array of arguments. The first argument is the program, the rest are interpreted as parameters to that program. By doing this, subprocess.run will try to format the arguments such that they cannot be used to do shell/code injection.

I also added a shlex.quote call around the formatting you passed in. This is a function that explicitly makes sure that no strange quotes or characters make it into the formatting you put in.

I am going to remove all of this now and change the code to be the following: 

        
    from subprocess import run

    def call_date_unsafe(formatting: str = None):
        command = "date"

        if formatting:
            if not formatting.startswith("+"):
                formatting = "+" + formatting
            command = command + " " + formatting

        out = run(command, capture_output=True, shell=True)

This is incredibly unsafe. subprocess.run is not inherently unsafe, but used this way where a raw string is passed as a command makes it more difficult for it to sanitize your input.

I also set subprocess.run to use shell mode. This makes it treat the command you pass in as a full shell script. This in turn means that you can run multiple commands in sequence.

    >> /dev/null; echo hello!

Interesting! It ran your echo hello! command! So what is going on?

Doing this, instead of having a sensible date command, you executed the following:

        
    $ date {{formatting}}

Here we are throwing away the output of the date command into /dev/null, which is a sort of black hole where anything you write will disappear. This makes it so that something else can be written to the output, in this case the output of the echo command, which is hello!

Hopefully you sense the consequences of this. Doing this, you can run anything you want on the system the application/website is running on. Including some really dirty stuff.
