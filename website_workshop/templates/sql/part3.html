SQL injection part 3

Interesting. An error appeared at the top talking about a syntax error!

Something like this is very typical when an input form exposes an SQL injection vulnerability (and it tells you the SQL error). The reason why can be found in the code that is responsible for the login logic: 

        
    try:
        r = db.execute("SELECT * FROM users WHERE name = " + form.username.data + ';').fetchone()
    except Error as e:
        flash('Failed to log in: ' + str(e), 'error')

Here, the developer (me) has just plainly concatenated your input to the end of the SQL query. So instead of the following: 

        
    SELECT * FROM users WHERE name = '{{user}}';

You have instead injected your own SQL 

        
    SELECT * FROM users WHERE name = '' test--';

The first single quote (') you added closed the previous string.

The double dashes (--) indicate a quote, and makes SQLite ignore the rest of the statement.

The 'test' part is not a valid SQL syntax, so SQLite complains about it.

How about we try logging in without providing an account? This is a very common thing to do as well. Looking at the code above, it looks like we are just getting the first row of whatever the query returns. This will often end up being the admin account.

Try entering the following: 

        
    ' or 1--

The single quote again closes the previous string

'or 1' is our own condition. It basically means "or true", which is always true.

-- again makes SQLite ignore the rest of the statement

As a result your query will look like this:

        
    SELECT * FROM users WHERE name = '' or 1--';

Which means we are selecting all users where one of the following is true:

  • The name is equal to ''
  • True

Since True is always True, we get every row.
