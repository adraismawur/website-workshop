How do we protect against this attack?

In part 1 there was also a login screen. If you were eager and tried to mess around with that one, you might have seen that it does not work. Here is the login form again:

{{ form.username }} {{ form.submit }}

The code that is responsible for the login logic for the above form looks like this: 

        
    try:
        r = db.execute("SELECT * FROM users WHERE name = ?;", (form.username.data,)).fetchone()
    except Error as e:
        flash('Failed to log in: ' + str(e), 'error')

The important part here is the presence of placeholders, indicated by the question mark. This indicates that a value needs to be replaced by something and cleaned up properly, in this case the username.

By using this placeholder and replacement, the value is sanitized and can be safely used. Feel free to try what you have learned in the above username input - None of the below attacks will work: 

        
    ' test--
        
        
    SELECT * FROM users WHERE name = '' or 1--';
        
        
    '; INSERT INTO users (name) values ('test');--

For more information, see the following:

  • Wikipedia - SQL injection
